Causal Parser：逻辑、位点与实验资格

本报告解释 V5 native-thinking 的 causal-site compiler 如何把自然语言 reasoning trace 转换成可审计的 retrieval、marker、progress 和 stop 位点。它描述实验注册规则，不报告任何 causal intervention 结果。

1. 核心结论与边界

一句话：现有 hybrid trace parser 负责恢复“模型写出了哪些事件”；causal-site compiler 负责决定“这些事件应该在哪些 token 上查询、干预或评分，以及这条轨迹允许支持什么因果命题”。

位点选择和统计 estimand 被严格拆成两个轴：surface grammar 决定位点，trajectory cohort 决定允许的实验解释。cohort 不会为了提高覆盖率而移动 token site。

使用的信息

原始输出、frozen output token IDs、prompt record spans、gold-city registry、hybrid parse。

不用于 running site 的信息

gold N 和最终 Total 数值不参与 event 构造、grammar 选择或 running-site 定位。

尚未决定

grammar-conditioned retrieval anchor、layer/head、ablation baseline、donor、patch window、full-path vs target-only metric。

2. 两层架构

① Hybrid parse恢复 event 序列、城市、rank evidence、字符边界与 association。
② Grammar compile逐 event 判断 rank/city 的真实先后顺序；不套固定 marker 模板。
③ Exact token map用 frozen tokenizer 重分词并要求 token IDs 完全一致。
④ Cohort gate保留所有位点，但按 trace 完整性限制可声称的 estimand。

因此所谓 “causal parser” 更准确地说是一个 grammar-aware causal-site compiler：它不替代已有文本 parser，而是消费 parser 输出并生成 machine-readable causal registry。

3. 第一层：恢复模型实际写出的 trace

rank_supported_episode

找到连贯的 1…M ordinal/count evidence。逐 event 使用 rank parser 提供的 city、rank、association 和 semantic span。

structural_extension

前面虽有 rank episode，但后面的 structural recap 增加了新城市。完整 recap 被单列为 secondary consolidation cohort。

structural_fallback

没有可靠 rank episode，但 bullet/indexed/unmarked 结构恢复出稳定的城市列表。

rank_evidence_core_span

如果 punctuation 与 core 被 tokenizer 合在同一个 token，shell 会记录为空；这表示在 token 层无法独立干预，而不是一个 parser failure。当前 3,027 个 rank/marker core 的右侧 spill 均为 0。

6. 字符 span 到 token span

  1. 使用模型对应的 frozen tokenizer 对完整 raw_output_text 重新分词。
  2. 要求重新得到的 IDs 与 generation 中保存的 output_token_ids 完全一致。
  3. 对字符 span 选择所有与之相交的 token，取最小覆盖区间。
  4. 记录 token interval、IDs、decoded text、left/right spill 和 full-sequence index。
  5. prompt source span 解码后必须确实包含对应城市。
Byte-level tokenizer 可以把同一个多字节 Unicode 字符拆成多个、共享字符 offset 的 token，例如 U+2029。compiler 因此要求 offset 左右边界分别单调，而不错误要求 token 字符区间彼此不重叠；token ID 精确一致性仍然是硬条件。

Transition 同时保留 full path 与 semantic target

Continue 保存 commit+1 … next-city-end，同时单独保存 next-city tokens；stop 保存 final-commit+1 … Total:-end，同时单独保存三-token Total: 。中间 token 数作为 interstitial diagnostic，不被静默截断。

8. 为什么 prefix 与 postfix 必须分开

Prefix rank

1. Chicago received a score.
rank core: 1→ retrieve query→ Chicago target→ item commit

rank 先出现，但 progress commit 必须等到包含城市的 semantic item 完成。

Postfix rank

Chicago received a score. Count: 1
retrieve query→ Chicago target→ rank core: Count: 1→ item commit

retrieval 必须在 city 之前查询；running update 则在后置 count 完成后才 commit。

旧的统一模板 marker_end(k) → city_end(k) 在 postfix grammar 中会把因果方向写反。这正是新 compiler 按 event grammar 选择位点的主要原因。

10. Hard gates、当前结果与待决项

  • 600/600 输入行成功编译
  • output re-tokenization 与 frozen IDs 完全一致
  • prompt source registry 解码后包含对应城市
  • primary cohort 在两模型中均非空
  • 446 条 primary 全部 site-complete
  • 当前 city_pre_d1 baseline 的所有 retrieval query 严格位于 city 之前
  • 所有 rank core 的 right spill 为 0
  • 所有 continue target 严格位于 commit 之后
  • 所有 stop target 严格位于 final commit 之后
  • duplicate / partial / evidence-sequence cohort 的 estimand 权限被强制执行
  • 所有 primary 均有独立 answer_query_v3
  • 没有 unresolved cohort
仍需人工决定：少数 Qwen primary 的 interstitial path 很长。当前最大 terminal-stop interstitial 为 698 tokens，最大 continue interstitial 为 460 tokens。compiler 同时保存 full path 和 semantic target，但没有事后设阈值。正式实验前需决定：full-path scoring、target-only scoring，或按 gap 长度预注册分层/排除规则。
